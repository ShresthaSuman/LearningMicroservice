# Discount gRPC Service

The Discount service stores and manages product discount coupons. It exposes a
gRPC API, uses Entity Framework Core with SQLite for persistence, and is called
by the Basket service when a basket needs discount information.

This document explains the service from the outside in: its responsibility,
folder structure, startup process, database model, gRPC contract, request flow,
local and Docker execution, and current implementation considerations.

## 1. What this service does

```text
Client service (for example Basket)
            |
            | gRPC over HTTP/2
            v
      DiscountService
            |
            | Entity Framework Core
            v
        SQLite database
```

The service currently supports four operations:

| Operation | Purpose | Lookup key |
|---|---|---|
| `GetDiscount` | Read a coupon for a product | `ProductName` |
| `CreateDiscount` | Add a coupon | Coupon payload |
| `UpdateDiscount` | Update a coupon | Coupon payload, including `id` |
| `DeleteDiscount` | Remove a coupon | `ProductName` |

The service uses product names as the lookup key. It does not currently
calculate a final basket price; it returns the configured discount amount and
description to the calling service.


Important package responsibilities:

Generated files under `obj` should not be manually changed. Edit
`Protos/discount.proto` instead and rebuild.

## 4. The gRPC contract

The public contract is defined in `Protos/discount.proto`.

```protobuf
service DiscountProtoService {
  rpc GetDiscount(GetDiscountRequest) returns (CouponModel);
  rpc CreateDiscount(CreateDiscountRequest) returns (CouponModel);
  rpc UpdateDiscount(UpdateDiscountRequest) returns (CouponModel);
  rpc DeleteDiscount(DeleteDiscountRequest) returns (DeleteDiscountRespose);
}
```

### Messages

```protobuf
message CouponModel {
  int32 id = 1;
  string productName = 2;
  string description = 3;
  int32 amount = 4;
}
```

`CouponModel` is the transport representation used by gRPC clients and
servers. It is separate from the EF Core `Coupon` class, even though Mapster
currently maps matching properties automatically.

The request messages are:

```protobuf
message GetDiscountRequest {
  string productName = 1;
}

message CreateDiscountRequest {
  CouponModel coupon = 1;
}

message UpdateDiscountRequest {
  CouponModel coupon = 1;
}

message DeleteDiscountRequest {
  string productName = 1;
}
```

The delete operation returns:

```protobuf
message DeleteDiscountRespose {
  bool success = 1;
}
```

`DeleteDiscountRespose` is currently misspelled in the contract. It is already
part of the generated API, so changing it requires updating the proto and all
clients together. A future breaking-contract cleanup could rename it to
`DeleteDiscountResponse`.

## 5. Startup process

`Program.cs` performs the following steps:

```csharp
var builder = WebApplication.CreateBuilder(args);
```

This creates the ASP.NET Core application builder and loads configuration from
`appsettings.json`, environment variables, and the selected environment.

### Step 1: Register gRPC

```csharp
builder.Services.AddGrpc();
```

This registers the ASP.NET Core gRPC infrastructure and enables the generated
service to be mapped later.

### Step 2: Register the database context

```csharp
builder.Services.AddDbContext<DiscountContext>(options =>
    options.UseSqlite(
        builder.Configuration.GetConnectionString("Database")));
```

`DiscountContext` is registered as a scoped dependency. Each gRPC request can
receive a context through dependency injection.

The connection string is:

```json
{
  "ConnectionStrings": {
    "Database": "Data Source=discountDb.db"
  }
}
```

When running locally, the SQLite file is created relative to the application
working directory.

### Step 3: Build the application

```csharp
var app = builder.Build();
```

At this point the service collection and configuration are turned into the
running ASP.NET Core application.

### Step 4: Apply EF Core migrations

```csharp
app.UseMigration();
```

This calls the extension method in `Data/Extension.cs`. Its intention is to
create or update the SQLite schema when the application starts:

```text
Application starts
       |
       v
Create a service scope
       |
       v
Resolve DiscountContext
       |
       v
Apply pending migrations
```

### Step 5: Map the gRPC service

```csharp
app.MapGrpcService<DiscountService>();
```

This binds the generated protobuf service contract to the
`DiscountService` implementation.

### Step 6: Map the root endpoint

```csharp
app.MapGet("/", () =>
    "Communication with gRPC endpoints must be made through a gRPC client...");
```

This is only a friendly browser/HTTP response. It is not a discount API
endpoint. Discount operations must use gRPC over HTTP/2.

### Step 7: Start listening

```csharp
app.Run();
```

## 6. Database model

The persistence model is `Model/Coupon.cs`:

```csharp
public class Coupon
{
    public int Id { get; set; }
    public string? ProductName { get; set; }
    public string? Description { get; set; }
    public int? Amount { get; set; }
}
```

The corresponding SQLite table is `Coupons`:

| Column | SQLite type | Key | Nullable |
|---|---|---|---|
| `Id` | `INTEGER` | Primary key, auto-increment | No |
| `ProductName` | `TEXT` | No | Yes |
| `Description` | `TEXT` | No | Yes |
| `Amount` | `INTEGER` | No | Yes |

`DiscountContext` exposes the table through:

```csharp
public DbSet<Coupon>? Coupons { get; set; }
```

The context also seeds three coupons:

| Id | Product | Description | Amount |
|---:|---|---|---:|
| 1 | `IPhone X` | `Iphone X is a good phone` | 100 |
| 2 | `IPhone 12` | `Iphone 12 is a good phone` | 200 |
| 3 | `IPhone 13` | `Iphone 13 is a good phone` | 150 |

The initial migration creates the table and inserts this seed data. EF Core
tracks the model snapshot so future migrations can detect schema changes.

## 7. Request processing in `DiscountService`

`DiscountService` inherits from the generated base class:

```csharp
public class DiscountService(
    DiscountContext dbContext,
    ILogger<DiscountService> logger)
    : DiscountProtoService.DiscountProtoServiceBase
```

Dependency injection supplies:

- `DiscountContext` for database access
- `ILogger<DiscountService>` for structured logging

Mapster converts between:

```text
CouponModel  <->  Coupon
gRPC model       EF Core model
```

### 7.1 Get discount

The request is:

```protobuf
rpc GetDiscount(GetDiscountRequest) returns (CouponModel);
```

Processing steps:

1. Read `request.ProductName`.
2. Search `Coupons` for the first matching product name.
3. If a coupon exists, map it to `CouponModel`.
4. If no coupon exists, create an in-memory fallback:

   ```text
   ProductName: "No discount"
   Description: "No discount in this product"
   Amount: 0
   ```

5. Log the selected result.
6. Return the response to the gRPC client.

The not-found case is intentionally returned as a successful response with
zero amount rather than as a gRPC error.

### 7.2 Create discount

The request contains a `CouponModel`.

Processing steps:

1. Map `request.Coupon` to `Coupon`.
2. Reject a null mapped result with `StatusCode.InvalidArgument`.
3. Add the entity to `dbContext.Coupons`.
4. Call `SaveChangesAsync`.
5. Log the created coupon.
6. Map the saved entity back to `CouponModel`.
7. Return the created coupon.

The database generates the `Id` when a new coupon does not provide one.

### 7.3 Update discount

Processing steps:

1. Map `request.Coupon` to `Coupon`.
2. Reject a null mapped result with `StatusCode.InvalidArgument`.
3. Mark the entity as updated with `dbContext.Coupons.Update`.
4. Call `SaveChangesAsync`.
5. Log the update.
6. Return the mapped coupon.

The update request should include the existing `id`. EF Core uses that key to
identify the row. The current implementation does not explicitly check that
the row exists before calling `Update`; error handling can therefore be
improved for production use.

### 7.4 Delete discount

Processing steps:

1. Read `request.ProductName`.
2. Find the first coupon with that product name.
3. If no coupon exists, throw `StatusCode.InvalidArgument` with `Coupon not
   found`.
4. Remove the entity from the context.
5. Call `SaveChangesAsync`.
6. Log the product name.
7. Return `{ success: true }`.

Deletion is product-name based, not ID based. This means product names should
be treated as unique by the business rules, although the current database
schema does not enforce a unique index.

## 8. Complete request flow

For a Basket-to-Discount call, the runtime flow is:

```text
Basket service
    |
    | DiscountProtoServiceClient.GetDiscount(...)
    | HTTP/2 + protobuf
    v
DiscountService.GetDiscount(...)
    |
    | DiscountContext.Coupons query
    v
SQLite Coupons table
    |
    | Coupon entity
    v
Mapster
    |
    | CouponModel
    v
Basket service receives discount response
```

The Basket service registers the generated client like this:

```csharp
builder.Services.AddGrpcClient<
    DiscountProtoService.DiscountProtoServiceClient>(options =>
{
    options.Address = new Uri(
        builder.Configuration["GrpcSettings:DiscountUrl"]!);
});
```

For local execution, Basket uses:

```text
https://localhost:5052
```

For Docker Compose execution, Basket uses the Compose service name:

```text
https://discount-gRPC:8081
```

Inside a container, `localhost` means the current container. Therefore the
Basket container must use `discount-gRPC`, not `localhost`, to reach the
Discount container.

## 9. Configuration and ports

### Local launch profiles

`Properties/launchSettings.json` defines:

| Protocol | URL |
|---|---|
| HTTP | `http://localhost:5002` |
| HTTPS | `https://localhost:5052` |

The service configures Kestrel to use HTTP/2:

```json
{
  "Kestrel": {
    "EndpointDefaults": {
      "Protocols": "Http2"
    }
  }
}
```

gRPC requires HTTP/2. A normal HTTP/1.1 browser request cannot invoke the
generated gRPC methods.

### Docker Compose ports

The root `compose.yaml` publishes:

| Container endpoint | Host endpoint | Purpose |
|---|---|---|
| `8080` | `6002` | HTTP |
| `8081` | `6062` | HTTPS/gRPC |

Container-to-container communication uses:

```text
https://discount-gRPC:8081
```

The container receives this database setting:

```text
ConnectionStrings__Database=Data Source=discountDb
```

This is a SQLite database path inside the container. The current Compose
configuration does not define a named volume for the Discount SQLite file, so
container recreation can remove its data. Add a volume if persistent data is
required.

## 12. EF Core migrations

The existing migration is:

```text
Migrations/20260923052052_InitialCreate.cs
```

It creates `Coupons` and inserts the initial seed records.

When the model changes, create a new migration from the project directory:

```bash
dotnet ef migrations add MeaningfulMigrationName \
  --project Services/Discount/Discount.gRPC/Discount.gRPC.csproj
```

Apply migrations manually when needed:

```bash
dotnet ef database update \
  --project Services/Discount/Discount.gRPC/Discount.gRPC.csproj
```

The application also attempts to apply migrations during startup through
`UseMigration`.

### Important migration implementation note

`Data/Extension.cs` currently calls `MigrateAsync()` without awaiting it:

```csharp
dbContext.Database.MigrateAsync();
```

Because `UseMigration` is synchronous, startup does not wait for the migration
to finish. This can cause a request to arrive before the database is ready and
can hide migration exceptions. A safer implementation should make the
extension asynchronous and await the migration before mapping or serving
requests, or use the synchronous `Migrate()` method during startup.

## 13. Error behavior

The service uses gRPC `RpcException` for some invalid operations:

```csharp
throw new RpcException(
    new Status(StatusCode.InvalidArgument, "Coupon not found"));
```

Current behavior:

| Situation | Current result |
|---|---|
| Missing product on `GetDiscount` | Successful fallback coupon with amount `0` |
| Null mapped create/update coupon | `InvalidArgument` |
| Missing product on delete | `InvalidArgument` |
| Database or unexpected exception | Propagates through ASP.NET Core/gRPC |

For a production API, validation should also cover empty product names,
negative amounts, missing descriptions where required, duplicate products, and
invalid update IDs.

## 14. Logging

The service logs:

- Product and amount returned by `GetDiscount`
- Coupon created
- Coupon updated
- Product deleted

The logging configuration is in `appsettings.json`:

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  }
}
```

Structured placeholders such as `{productName}` and `{amount}` allow logging
providers to index values separately from the message text.

Avoid logging sensitive payment or personal information if the model is later
extended with such fields.

## 15. Mapping with Mapster

The service relies on convention-based Mapster mappings:

```csharp
var coupon = request.Coupon.Adapt<Coupon>();
var couponModel = coupon.Adapt<CouponModel>();
```

This works because the source and destination properties have matching names
and compatible types:

```text
Coupon.Id          -> CouponModel.id
Coupon.ProductName -> CouponModel.productName
Coupon.Description -> CouponModel.description
Coupon.Amount      -> CouponModel.amount
```

If names or types diverge, configure an explicit Mapster mapping instead of
assuming the convention will continue to work.

## 16. Design and production considerations

The service is a learning-oriented implementation. Before production use,
consider the following improvements:

1. **Await startup migrations.** Ensure the database is ready before requests
   are accepted.
2. **Validate all inputs.** Reject blank product names and invalid amounts.
3. **Use a clear discount meaning.** Document whether `Amount` is a fixed
   currency value or a percentage.
4. **Enforce product uniqueness.** Add a unique index if one coupon per product
   is required.
5. **Use stable lookup identifiers.** Product IDs are usually safer than
   product names because names can change and may differ by casing.
6. **Improve update handling.** Load the existing row, return a clear
   `NotFound` error when it does not exist, and avoid unintentionally replacing
   all fields.
7. **Use suitable gRPC status codes.** For example, `NotFound` for a missing
   coupon and `AlreadyExists` for duplicate products.
8. **Protect database persistence.** Add a named Docker volume or move the
   service to a managed database when data must survive container recreation.
9. **Separate application layers as the domain grows.** A larger service would
   normally separate contracts, application logic, domain rules, persistence,
   and transport endpoints.
10. **Add automated tests.** Cover service methods, validation, migrations, and
    the gRPC contract.
11. **Use production TLS.** Replace development certificate bypasses with a
    certificate trusted by all communicating services.
12. **Review package versions.** The project currently uses prerelease package
    versions for gRPC, Mapster, and EF Core tooling. Pin compatible stable
    versions before production deployment.

## 17. Quick mental model

Remember the service in five steps:

```text
1. discount.proto defines the API.
2. Build generates the C# gRPC types.
3. DiscountService implements the generated service.
4. DiscountContext maps Coupon to the SQLite Coupons table.
5. Program.cs wires everything together and starts HTTP/2.
```

If a client call fails, inspect the system in this order:

```text
Client URL and TLS
        |
        v
HTTP/2 and gRPC contract
        |
        v
DiscountService method
        |
        v
Mapster conversion
        |
        v
EF Core query/save
        |
        v
SQLite file and migrations
```
